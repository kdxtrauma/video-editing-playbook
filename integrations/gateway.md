# Подключение GPT, Claude, DeepSeek и локальных моделей
Если модели уже доступны через ваш Harness, предпочтительнее его собственный model adapter. Альтернативный model_gateway.py принимает локальный профиль JSON {provider:"openai-compatible" или "anthropic", url:"полный URL endpoint", model:"реальное имя доступной модели", key_env:"имя переменной окружения", max_output_tokens:4096, timeout:180}. Секреты только в окружении, профиль вне публичного git. Не указаны фиктивные модели, адреса или ключи. Совместимость конкретной версии API нужно подтвердить smoke test. Для некоторых OpenAI-compatible моделей требуется другой параметр лимита — адаптировать согласно их API.
В pipeline config для producer/director_a/director_b/judge/editor/repair можно указать ["абсолютный python","абсолютный model_gateway.py","абсолютный profile.json"]. Использовать разные профили для независимых режиссёров. Задать лимит output tokens, вызовов и провайдерский бюджет отдельно. Gateway передаёт JSON контекст на выбранный вами endpoint: разрешайте передачу только согласованных и обезличенных материалов. Он не отправляет файлы и не поддерживает наблюдение или финальную критику. Для capabilities, observe, critic необходимы реальные media adapters; text-only не может пройти полноценную приёмку.
Не загружать конфиги, результаты, ключи и приватные медиа в GitHub. Для подключения к собственному Harness реализовать stdin/stdout контракты из engines/protocol.md. Проверить независимость контекстов, фактический результат и отрицательные сценарии до использования.
