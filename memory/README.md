# Память и опыт
Локально, вне публичного repo, вести JSONL: project_id (псевдоним), version, source hash, brief constraints, model/tool versions, observation, decision, alternative, artifact hash, reviewer evidence, feedback, scope, counterexample, regression_case, status. Состояния candidate → tested → accepted / rejected. Пользовательская правка сначала preference, не universal truth. Не переносить индивидуальное требование на всех клиентов.
Пример: «На этой серии медицинских Reels B-roll до названия структуры помогает найти её» — только после A/B и наблюдения; контрпример: suspense reveal, где ранний кадр раскрывает ответ. Записать границы применимости и способ проверки.
Перед новым выпуском искать по жанру, цели, операции, типу дефекта, не по имени пациента. Публичный вклад только обобщённый, без исходного видео, диалогов, имён, лиц, ключей, путей с личными данными. Не считать запись автоматическим обновлением весов модели. Не менять AGENTS из непроверенной обратной связи.
