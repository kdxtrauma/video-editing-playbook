# Постоянная инструкция монтажному агенту

Используй эту базу при монтаже любого видео. Если она вложена в рабочую папку, добавь ссылку на этот файл в инструкции корня монтажного проекта, сохранив действующие правила. Исходники, журнал выпуска и результаты находятся в локальной папке выпуска. Запиши используемую версию базы через git rev-parse HEAD.

1. Из задания извлеки формат, аудиторию, обещание, площадку, обязательные элементы, доступные источники и набор поставки. Открой handbook/06-genres.md, выбери основной жанр и, при необходимости, дополнительный. Для нового жанра выведи подход из цели, ограничений и соседних форм, отметь предположение. Задание автора и спецификация получателя имеют приоритет.
2. Прочти handbook/01-story-and-cut.md, затем главы по реально нужным операциям из README.md. Для подкаста дополнительно загрузи editors/chatgpt/directing.md. Проверь фактически добавленные материалы Claude в editors/claude/. Одно задание для будущего вклада не является отдельным мнением редактора.
3. Установи, какие компоненты доступны: последовательное видео, отдельные кадры, аудио, таймкодированная речь, управление NLE и обратное чтение результата. Запиши в журнал, что проверил. Отдельные кадры не подтверждают интонацию и непрерывность движения. Продолжай независимую работу при недоступности одного инструмента.
4. Для каждого значимого эпизода выбери изменение в истории, лучший источник, вход, выход и слышимую точку. Для вставок и эффектов используй templates/ и главы 02/03. В спорном месте сравни две версии одного решения на одинаковом звуковом уровне. Опиши то, что зритель должен различить после просмотра.
5. Сначала сохрани план, затем физически собери монтаж на рабочей копии. Для простого речевого CFR-черновика могут подойти tools/podcast_edit_engine.py и tools/podcast_director.py. Для сложного видео работай средствами NLE, Fusion, Fairlight или другого подходящего инструмента в пределах его реальных возможностей. Проверяй операции через считывание таймлайна, повторное открытие или экспорт. Успешный вызов инструмента подтверждает исполнение команды, но зритель видит и слышит только результат.
6. Проверь мастер по handbook/05-postproduction.md. При дефекте используй handbook/07-workbench.md, исправь и повтори проверку затронутых версий. Сдай проект, согласованные файлы и короткий отчёт с фактическими результатами и ограничениями. Публикация базы не означает разрешения на публикацию частного выпуска.

## Обязательный контур Academy v1
Для каждого нового выпуска загрузить [academy/README.md](academy/README.md) и [agents/orchestrator.md](agents/orchestrator.md). Это дополняет, не отменяет правила выше. Не ограничиваться ответом-планом: если инструменты доступны, выполнить монтаж и независимую проверку. Минимум три концепции суммарно от независимых режиссёрских ролей при делегированном стиле; если автор дал точный референс, вариации внутри него. Использовать [контракты ролей](agents/roles.json), [карточки](skills/catalog.json), [контур валидации](engines/README.md) и [hard gates](quality-control/README.md). Не утверждать, что Harness уже подключён или Claude внес вклад, пока это не проверено. Не считать результат approved при неизвестном обязательном gate. Бюджет, права и доступ к инструментам проверяются на каждом выпуске.

## Контекстная школа v2
Перед планированием применяй skills/retrieve.py для подбора карточек по реальному жанру, дисциплине и ограничению. Лабораторный сценарий является гипотезой упражнения, не обязательным эффектом. Проверь триггер, критерий и контрпример. Не путать 2210 учебных единиц с 2210 уникальными техниками. Для model adapter см. integrations/gateway.md. Отделяй факт доступности модели от факта способности просмотреть и прослушать медиа.

## Подключение к локальному Harness
Если эта база впервые подключается к работающему Harness, выполни [инструкцию интеграции](integrations/HARNESS-BOOTSTRAP.md) в отдельной ветке. Не заявляй о готовой интеграции до локальных тестов и независимой проверки реального видео.
